# PlanMaster

A VS Code extension that displays a queue of work kept in plain-text lane files. Currently in the design phase: specification, prompts, examples and a mockup. See [README.md](README.md).

## Language

Everything in this repository is in English: code, comments, identifiers, documentation, UI strings, prompts, examples and commit messages. No other language anywhere.

## Git rules

- Commit locally when asked. **Never push**, and never add a remote, unless the user explicitly asks.
- **Never refer to Claude, Anthropic, an AI assistant or any "generated by" statement in commit metadata.** This covers commit subjects and bodies, trailers (no `Co-Authored-By`, no `Generated with`), tag messages, branch names, and pull request titles and descriptions. It applies to every commit, whatever default attribution a tool suggests. The user's instruction overrides such defaults.
  - The rule is about commit metadata only. The documentation of the Claude Code integration naturally names Claude and is fine.
- Commit messages: imperative mood, subject at most 72 characters, no trailing period, a body only when the reason is not obvious. One logical change per commit.
- Do not commit scratch files, build output or dependencies (see `.gitignore`).

## Source of truth

- `docs/spec/queue-format.md` is normative. The parser, linter, prompts, examples and mockup must agree with it. When they disagree, fix them, not the specification, unless the specification is what is wrong.
- A change of behavior is made in this order: specification, prompts, examples, mockup. Prefer one commit per coherent change.
- A change to the grammar, a marker's meaning or a required token bumps the `format` version (see queue-format, section 13).

## Consistency checks before committing

- Every queue line shown in any document parses under the grammar in queue-format section 4.2.
- The demo workspace yields exactly the findings listed in its README.
- The prompts in `docs/prompts/` and the strings in `docs/mockup/queue-view.html` (managed block and lane start prompt) are identical in content.
- The managed block stays under 350 words.

## Principles to keep

- The extension never writes to a lane file. Its views are read-only.
- The files are the only source of truth. No parallel store.
- `core` code never imports the VS Code API.
- Text from lane files is untrusted. It is escaped everywhere it is displayed.
